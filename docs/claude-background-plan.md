# Claude Desktop 背景扩展方案

状态：最小换肤验证、原生调试入口的只读连接及断开重连已通过；用户已审阅通过共用管理器 UI。正式源码已扩展至完整按钮流程、视频/动图和独立启动动画，当前进行隔离开发验收；真实 Claude 媒体播放、恢复及跨进程重启验收尚未完成。

## 目标与首版范围

现有管理器增加 Claude Desktop 页面换肤能力，继续共用主题库、素材、编辑器、预览、导入导出及社区流程。当前范围为 Windows 的已验证 Code 页面，包含图片、动图、MP4 视频、取景与缩放、透明度、播放速度、暂停/继续、默认重置、取消皮肤及独立启动动画设置。

当前范围不包含 macOS 和 Claude Cowork/其他页面的完整适配。Codex 专用 CSS 不注入 Claude；复用主题的媒体素材与通用参数，页面样式各自适配。

## 已验证的事实

本次验证跨越 2026-11-06 / 2026-11-07，环境为 Windows、Claude 安装包 2.9939.4.0（应用版本 2.9939.4）、Electron 44.4.3。

- 当前 Claude 进程没有现成的 CDP 监听端口。
- 使用原版 Claude.exe 和 `--remote-debugging-address=127.0.0.1 --remote-debugging-port=19471` 做受限启动，子进程退出码为 1，明确输出 `Claude: refusing to start — a debugging or network-override switch is present on the command line.`。未关闭或重启原有 Claude 进程。
- 原版安装资源的启动逻辑也明确拒绝 remote-debugging-port / remote-debugging-pipe；存在开发者授权校验。因此不能把 Codex 的启动参数照搬为 Claude 的默认接入方案。
- 本机已有 allowDevTools 配置，通过 Claude 原生菜单 Developer → Show Dev Tools 能打开 Code 页面开发工具。本次未修改开发者设置；控制台解除粘贴保护由用户手动完成。
- 所检查的 Code 页面为 `app://localhost/epitaxy/...`；当前页面没有 iframe/webview，不代表所有版本或其他页面都没有。
- 注入的 JPEG 背景能解码，CSS 能安装并实际显示。复用了现有 `windows/presets/synthwave-grid.jpg` 的缩小副本；画面包括主区、侧栏和顶部。
- 切换到另一个现有 Code 会话后，背景保持显示。未发送消息，也未执行会话中的指令。
- 用户要求保留效果后，只读核对确认临时运行时对象、样式节点和根标记仍存在。此前发出的恢复操作没有取得成功结果，不能记为恢复通过。

本地截图、脚本与核对结果位于被 Git 忽略的 `artifacts/claude-background-spike/`。截图含本机会话内容，只作本地证据，不随方案提交或公开。

## 运行时适配

保留当前 Windows/macOS 适配层，在其内部按目标应用区分连接和页面渲染；不建立通用插件框架，也不复制整套管理器。

需要应用差异的部分：

1. 应用发现、安装版本、进程身份、连接入口和页面选择。
2. Code 页面的布局标记、背景清理和 CSS。
3. 应用级活动主题、暂停、连接状态与恢复状态。

继续共享的部分：主题及素材库、媒体处理、通用主题参数、主题编辑、导入导出，以及适合共享的连接传输与生命周期逻辑。CDP 传输仅在 Claude 有获准且可验证的入口时使用。

不要放宽现有 Codex 页面验证来接受任意 app:// 或浏览器页面。Claude 使用自己的进程/页面身份校验，分别确认安装实例、连接端点和 Code 页面。

验证原型识别到了 `main.dframe-content`、`aside.dframe-sidebar` 和 `.dframe-root`。另一个外层 `.bg-surface-1` 祖先会遮住背景，原型用限定在 `.dframe-root` 祖先上的规则处理；正式实现需依据当时页面结构继续核对。这些是该版本的实测节点，不是官方稳定接口。

## 状态、界面与主题兼容

- 管理器增加目标应用选择：Codex / Claude。应用按钮明确显示当前目标。
- 素材和主题只保存一份；两个应用分别保存当前主题引用、已应用版本、暂停和连接状态。
- 切换界面目标只切换显示，不自动给另一个应用换肤。每次操作在发起时固定目标，回执和事件携带相同目标，避免执行中切换选项后串写。
- 旧状态默认属于 Codex，保持现有主题引用和存储路径可读；Claude 状态新增到独立命名空间。Claude 应用时保存独立媒体快照，暂停和继续不依赖共享库当前文件；采集期间与共享库写入互斥。
- 参数按目标能力启用；不支持的项明确显示原因，不默默使用 Codex 的效果。
- 应用主题时复用已有连接；首次连接若需要用户操作或重启，明确展示实际步骤，普通切换不重复要求。
- 首版暂不支持 Claude 专用任意 CSS 包。社区主题的素材和通用参数与 Codex 定制样式分别处理，保留原主题与许可，不宣称完全兼容。

## 注入与恢复的实现方向

采用独立样式节点、应用自己的根标记和可撤销的运行时状态；覆盖注入内容时更新同一个实例。优先用 CSS 规则处理新出现的同类节点，确需观察 DOM 时再增加有明确清理方式的 observer。

普通换肤不修改 Claude 官方安装文件，不改用户原生外观配置。恢复时移除管理器创建的样式、背景媒体、根标记和监听器；如果确需改已有属性，则记录原值并只恢复自己仍持有的修改。

原型提供了 restore 方法，但本轮没有验证通过。正式实现必须补验：恢复到注入前背景、重复恢复无副作用、恢复后重新应用，以及会话切换/窗口重建后恢复。方法存在不代表恢复验收通过。

## 2026-11-08：自动连接入口探针

本机 Claude 已升级为 MSIX 4.16336.0.0，旧版本的换肤实测不自动证明新版本兼容。

新版本原生 Developer 菜单的 `Enable Main Process Debugger` 调用 Node Inspector 的 `open()` / `close()`，提供了无需重启的候选连接入口。它与 Chromium renderer 的远程调试启动参数不同；源码检查不等于已连接，也不等于官方承诺支持第三方换肤。

已准备 `tools/claude-connection-probe.mjs`，用法：

```powershell
node tools/claude-connection-probe.mjs
```

探针只执行以下只读操作：

1. 从已注册 Claude MSIX 安装和运行进程查出唯一主进程。
2. 仅访问该主进程拥有的回环监听端口，核对 Inspector 端点形状及实际 PID/可执行文件路径。
3. 通过固定表达式获取 Code webContents 的结构标记和应用版本，不采集会话 URL、标题、文本、输入或凭据。
4. 确认第一条连接已关闭后，再建立第二条连接，分别核对页面，以验证断开重连。

探针不提供任意表达式或网络地址参数，不开启/关闭调试器，不注入样式、不改背景，也不终止或启动 Claude。它不接入正式管理器。

无调试端口路径实测返回 `awaiting-user-enabled-debugger`，未自行开启调试器。用户随后明确授权并手动启用原生开关，真实连接实测结果为：

- 回环端点 `127.0.0.1:9229` 属于已注册 Claude 主进程 PID 4072；运行时身份与安装路径一致。
- 运行中应用版本为 4.16336.0，Electron 44.9.3。
- 两次连接均识别到同一 Code 页面（webContents id 2、type window），Code 路由、主区和侧栏标记均为 true，frame 数为 0。
- 第一条 WebSocket 确认关闭后才建立第二条，第二条也确认关闭；探针正常退出，`reconnected=true`。
- 本轮仅执行固定只读表达式，未改变外观、未重启 Claude、未开启 Chromium 远程调试。

原始脱敏回执保存在本地忽略目录 `artifacts/claude-connection-probe/connected.json`。独立源码复核通过；没有运行完整仓库测试或构建。

因此可以按“用户启用原生 Node Inspector → 验证主进程身份 → 定位 Code webContents → 执行受限页面操作”的连接方向继续开发。当前只读连接成功不等于自动背景应用成功；下一阶段才开发并验证独立 Claude 换肤运行时。

原生主进程调试器具有访问主进程的能力，不能作为普通页面连接无提示开启。初次及后续进程未开放入口时，界面应明确说明手动启用步骤；跨 Claude 重启是否需要重新启用、客户端升级后兼容性、长期断线恢复尚未实测，不能承诺一次授权永久有效。验证结束应通过同一菜单关闭，不把该入口默认开启写入正式产品。

本轮结束时，用户明确选择“暂时保留调试入口”，因此保持开启，未验证关闭后的端口消失。上述建议关闭入口的默认处理不覆盖用户本轮的选择。

用户已通过左侧图标竖栏界面审阅。显示名统一为 Claude Desktop，使用窄 `claude.*` 契约接入 Windows 原生 Inspector、应用/暂停/继续/恢复与独立参数保存。主题库和媒体预览共用；活动图片、参数覆盖与幂等操作回执保存在 `claude-desktop/`，旧 Codex 状态路径保持原样。

首块接受静态 JPEG、PNG 和 WebP，拒绝动画与自定义 CSS。支持取景、缩放、遮罩及已验证面板的透明度；气泡透明度因缺少可靠选择器暂不开放。调试入口只由用户手动开启，管理器不修改原生配置或官方安装。页面刷新后需要重新应用。

## 2026-11-09：完整流程、动态媒体与启动动画

- 详情面板复用同一组件，接通应用、下载、编辑保存、暂停/继续、默认重置、刷新和取消皮肤；取消确认框不发送变更。导入的保存并应用、社区下载后应用固定操作发起时的目标。
- 共享库中的 JPEG、PNG、WebP、GIF、APNG 和 MP4 通过现有媒体解析与限制校验。Claude 使用独立图片/视频元素，支持循环静音视频及播放速度；媒体加载成功后替换旧背景，失败保留旧显示，暂停/恢复释放自有资源。
- Claude 参数独立存储；保存当前皮肤参数会即时刷新，暂停时只更新保存状态。保存成功与当前显示更新失败分别反馈。默认重置使用既有恢复主题的默认参数，不受其 Claude 参数覆盖记录影响。
- 启动动画复用默认动画及视频播放/跳过层，设置单独保存在 `claude-desktop/`。可选共享库视频或恢复默认；选中素材已不存在时使用默认动画并保留诊断。普通换肤和首次接入当前页面不播放，新建或重载的 Code 文档每个文档最多播放一次。
- Claude 主进程内的控制器在管理器关闭后继续维护背景及新页面监听；暂停和取消皮肤会注销控制器、监听器及其持有的背景/启动动画。状态读取不会重新安装。任一应用使用中或暂停中的主题都受共享库删除保护。
- Claude 整个进程退出后，内存控制器随之消失；需要在原生调试入口可连接时重新应用或更新启动设置。尚未实现无需管理器重连的跨进程自动恢复。
- 正式运行时源在 `runtime/claude-renderer.mjs`，Windows 镜像由 `tools/sync-runtime-assets.mjs` 生成，打包器通过生成资源清单收集它；不在静态 `packaging/shared-resources.json` 中重复声明同一目标。

本轮隔离证据保存在本地忽略目录 `artifacts/claude-parity-20261109/`。隔离检查不证明真实 Claude 的 CSP、视频解码或像素外观，也不替代用户实机验收；本轮未重新构建 EXE、未连接或操作真实 Claude。
