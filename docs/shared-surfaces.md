# 统一界面背景

皮肤通过一套公共背景规则处理原生面板，不再为每个页面分别设置不透明度。
这套规则用于设置页、右侧工具区、底部终端外壳、来源卡片、输入框、浮层，以及
使用相同原生背景类的新区域。

## 参数入口

Windows 管理器在“主题设置”中提供“面板不透明度（输入框、工具面板等）”滑块，
创建自定义主题时也提供同一选项。范围为 0%～100%，默认 80%，数值越大越不透明。
修改后保存主题；如果编辑的是当前活动主题，会沿用现有保存流程刷新皮肤。
设置按主题保存，切换、导入和导出主题时一并保留，与消息气泡不透明度互不影响。

主题契约使用可选字段 `art.surfaceOpacity`（0～1），缺失时按 `0.8` 处理，
Windows/macOS 注入器都读取该字段。渲染器将其投射到公共 CSS 变量：

```css
--ds-surface-opacity: .80;
--ds-surface-blur: 10px;
```

`opacity` 在这里表示**背景不透明度**：`0` 为完全透明，`1` 为不透明；
`blur` 表示背景模糊半径，`0px` 为不模糊。它们组合成
`--ds-surface-background` 和 `--ds-surface-filter`，文字和图标不设置整体透明度。
模糊半径仍由共享 CSS 设置，不增加独立页面或每个面板的设置。

不要复用 `--ds-theme-surface-opacity`：该变量是既有社区 Safe CSS 的元素
`opacity` 接口，改变其语义会连带改变文字、图片等内容。

## 容器识别与动态页面

`runtime/renderer-inject.js` 集中维护 `SURFACE_CLASSES` 和
`SURFACE_BOUNDARIES`，识别原生中性背景类及语义容器，不匹配模块 hash、文字、
颜色像素或截图位置。新区域使用相同背景类时自动接入；只有引入新的原生背景
类型时才需要补充这份识别列表，不需要另写颜色和模糊规则。

- 外层容器标记 `data-ds-surface="panel"`，绘制一次公共底色和背景模糊。
- 内层重复背景标记 `clear`，防止层层叠加后重新变成实心。
- 整个应用的外层背景包装只清空，不把所有内容变成一个大面板。
- 浮层和吸顶容器保留独立底色，避免内容滚动穿透。
- 使用现有合并调度器处理节点增删及背景类变化；清理皮肤时恢复原有标记。

样式位于 `dreamskin-surfaces` 层。它覆盖旧基础样式中的背景和模糊声明，
既有 `dreamskin-community` 层仍可优先覆盖公开部件。

## 特殊渲染层与边界

差异视图沿用原来的原生接口，通过 `--codex-diffs-surface-override` 和局部
`--color-surface` 清除底色；不改新增、删除、语法及选中高亮。

2026-09-25 对运行中的客户端脚本做只读检查，确认终端初始化启用了
`allowTransparency`，并从 `--color-codex-terminal-background` 读取背景。
皮肤将该专用变量设为透明，由终端外部公共面板绘制底色，不降低 canvas 的
整体 opacity、不遍历 React 内部实例，也不改终端输出。已经打开的终端可能
缓存旧 theme；应用新皮肤后需要重新打开终端标签，或等待客户端重新读取主题。

媒体、网页/webview 内容、代码块、消息正文、主题预览以及按钮和选项的语义背景
不纳入通用清空规则。消息气泡仍使用原有独立设置。未来使用独立 iframe、封闭
Shadow DOM 或没有可识别接口的区域，不能承诺自动穿透，需要先确认其背景接口。

## 同步与验证

修改 canonical 文件后运行 `node tools/sync-runtime-assets.mjs`，将共同规则
同步到 Windows 和 macOS。不要直接维护两份平台 CSS 或 renderer。

已按用户要求完成 Windows 便携版构建，并核对打包运行时文件与源码的哈希一致。
未运行自动化测试或可视化验证。后续手动验收应包括：
设置页切换、空/已打开的右侧面板、底部终端、来源卡片、首页/会话输入框、
菜单弹窗、深浅色切换和暂停/恢复皮肤，并检查文字、高亮和主题预览保持正常。
